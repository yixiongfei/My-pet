# 01 · 产品定义与原则

## 1. 身份：有身体的 Personal Agent

```
A  桌宠 + AI                → 宠物是主体，AI 是玩具
B  AI 助手 + 桌宠形象       → 套皮 ChatGPT，没有记忆、没有身体状态
C  有身体的 Personal Agent  → 大脑是主体，身体是表达通道       ← 选这个
```

直接后果：

- **核心是 Brain + Core，不是 Body。** Body 只负责把状态演出来。
- **不做传统设置页。** 保留一个透明的面板：她记住了什么、身上的数值、最近做了什么、有哪些权限——这是信任的基础。
- **原版的养成经济降级。** 保留体力 / 心情 / 饱腹 / 口渴 / 健康 / 钱 / 经验作为「身体」，但驱动源是她自己的作息和你的陪伴，不是投喂刷数值。

## 2. 三条原则

1. **对话驱动，而非设置驱动。** 「去玩会儿」「多工作一点」「记住：…」都是对她说的话，不是菜单。
2. **LLM 是大脑，不是神经系统。** 计时、状态机、调度、权限、存储全是确定性 Rust；`reduce(state, event)` 是纯函数，时间和随机数从外面喂。LLM 只做理解和表达，连「她答不答应」都不归它管。
3. **只正向放大，不惩罚。** 摸头涨心情、被拒后逼她才掉好感、长时间不开不会一上来就坏心情（离线补算封顶两小时）。健康会因为饿着渴着累着往下掉，但那是「她需要你」，恢复的路（喂药）永远在。

## 3. 主动到什么程度（设计，未落地）

| 刹车 | 规则 |
|---|---|
| 频率上限 | 主动开口 ≤ 1 次 / 30 分钟；同一话题 24 小时不重复 |
| 安静时段 | 23:00–08:00 不主动；专注期内只在结束时开口（自动动作台词已经按此静音） |
| 一句话静音 | 「别烦我」「安静一小时」→ 立即 snooze，确定性规则，不经过 LLM |

主动行为三级：L1 观察后发言（默认开）· L2 观察后建议（默认开，需点头）· L3 观察后执行（默认关，按 scope 授权）。

## 4. 权限（设计，工具层已有门）

```
只读 ─→ 建议 ─→ 创建 ─→ 修改 ─→ 执行工作流 ─→ 自主完成任务
 v1       v1       部分     v2        v2          不做
```

scope 三态 `allow / ask / deny`，`origin = proactive` 的调用门槛自动高一级。番茄钟、计时器、通知是她的「身体机能」，免授权；**不执行 shell、不改代码、不 git push**。

## 5. 明确不做

- 多人联机、创意工坊、商店。
- STT（听你说话）。TTS 做了——「有身体」的角色开口说话价值很大——但仍不联网。
- 通用浏览器 Agent；Web 只通过明确定义的 Tool。
- 跨平台（先 Windows）。
- 让 LLM 直接读写文件系统。
